# Reopened Phase 3 implementation plan

Starting point: Phase 2 checkpoint `c0f54b30b149a33279649d7c17afb511867f5c05`.

## Gap

The repository already has signed execution tickets, workspace freshness validation, authenticated claim/heartbeat/complete/cancel APIs, `LocalExecutionWorker` and a sandboxed `CodexCliExecutor`. The missing corrected-flow link is from an API-Key-owned `APPROVED` planning session to a specifically configured local workspace/worker. The server must not guess a workspace root and approval must not itself grant arbitrary filesystem access.

## Scope

1. Add an API-Key session action that prepares execution only from `APPROVED`, with exact Plan version, worker identity and a normalized workspace descriptor supplied by the local client.
2. Reuse the existing signed, expiring, worker-bound execution ticket and duplicate prevention. Return the ticket only once to the authorized caller; never persist plaintext.
3. Expose execution ID/status/results on the Planning session and add session-level cancellation that delegates to the execution state machine.
4. Add a supported CLI/worker command that consumes the ticket, validates the local Git workspace/source revision, runs the installed Codex CLI and reports sanitized results.
5. Update the dashboard from “approved/inert” to queued/executing/result states without moving execution authority into the web server.
6. Run the existing token benchmark variants on the same tasks and report limits honestly.

## Mandatory negative tests

- Unapproved/rejected/cancelled Plan execution.
- Wrong API Key, Project, worker or workspace.
- Path traversal/symlink/out-of-root workspace.
- Stale branch/commit/file hash/context.
- Duplicate prepare/claim, ticket replay/expiry/tampering.
- Cancellation, timeout, worker disconnect/lease recovery and filtered logs.
- No raw shell generated by Planning Provider is executed.

## Gate

Phase 3 passes only when an Approved Plan from this API-Key session is actually executed by the validated local Codex CLI worker, results return to the same session, and all security/reliability regressions pass. It must remain blocked if the real installed Codex CLI cannot be verified.
